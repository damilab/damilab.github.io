# 논문 채택 소식을 News 해설 기사로 만드는 규칙

논문이 학회에 채택됐을 때 News 에 올리는 **해설 기사**의 작성 규칙이다.
2026-08 EMNLP 5편 + ICLR 2편을 만들면서 실제로 부딪힌 것만 적었다.

이 파일이 규칙의 **유일한 원본**이다. `CLAUDE.md` 와 `AGENTS.md` 가 이 파일을 가리킨다.
어느 도구로 작업하든 같은 규칙을 따른다.

기본 편집 규칙(PDF 금지, 바이트 단위 편집, `git add -A` 금지)은
[../WEBSITE_MAINTENANCE.md](../WEBSITE_MAINTENANCE.md) 에 있다. 여기서는 기사 관련만 다룬다.

---

## 1. 단위와 제목

**논문 1편 = 글 1개.** 여러 편이 한꺼번에 채택되면 허브 글을 하나 더 만든다
(`news/59` 참고). 허브는 배너 + 논문 목록만 담고, 상세는 논문별 글이 맡는다.

제목이 두 군데에서 다르다. 헷갈리기 쉬우니 표로 둔다.

| 위치 | 형식 | 예 |
| --- | --- | --- |
| News 목록 카드 (`news.json` 의 `title`) | `<연구 이름> 연구 <학회> Accept` | `SafeBranch 연구 EMNLP 2026 Accept` |
| 기사 안 `<h1>` (`articles.py` 의 `head`) | 한글 평서형 헤드라인 | `안전은 궤적 전체가 아니라 한 걸음에서 갈린다` |

목록은 "무슨 일이 있었나"를, 기사는 "무엇을 풀었나"를 말한다.
목록 카드를 기사 헤드라인으로 채우면 무슨 소식인지 안 보인다.

**같은 제목 카드를 여럿 만들지 않는다.** `news/45`, `news/46` 이 둘 다
`연구실 논문 ICLR 2026 Accept` 라서 목록에서 구분이 안 됐다.

## 2. 절 구성

다섯 절로 **고정**한다. 순서도 바꾸지 않는다.

```
배경 → 제안 방법 → 실험 설정 → 결과 → 의의
```

`왜 이 문제인가`, `어떻게 풀었나` 같은 의문형은 쓰지 않는다. 절 제목으로 서면
문장이 끊긴 느낌이라 붕 뜬다.

- **배경** 문제 상황과 기존 방식의 한계. 중간에 원문 Figure 1 을 넣는다
- **제안 방법** 무엇을 어떻게 했는지. 논문이 던진 질문이 있으면 인용구로 옮긴다
- **실험 설정** 벤치마크·모델·비교군·지표를 `dl` 목록으로
- **결과** `(1)`~`(n)` 번호 문단으로 서술
- **의의** 남색 박스 한 문단

## 3. 문체

**본문은 경어체 `~습니다`, 제목은 평서형.** 한국어 기사의 표준이다.

**AI 냄새를 만드는 두 가지를 피한다.** 이게 가장 중요하다.

- **고유명사를 뭉개지 않는다.** `네 개 타깃 모델` 이 아니라
  `Qwen3-235B, LLaMA-3.3-70B, GPT-4o-mini, Gemini-2.5-Flash` 로 쓴다.
  `기존 최강 baseline` 이 아니라 `Important message` 로 쓴다.
  벤치마크 버전(`AgentDojo v0.1.34`), 데이터 규모(`949쌍`), 기간까지 적는다
- **`A가 아니라 B다` 대구를 반복하지 않는다.** 한 기사에 두 번 이상 나오면 고친다.
  대구를 쓰고 싶어지는 자리는 대개 **구체적인 수치로 대체할 수 있는 자리**다

**결과는 라벨 카드가 아니라 문단으로 쓴다.** `네 모델 전부에서 CSR 1위` 같은
짧은 라벨 + 한 줄 설명 카드는 사람이 잘 안 쓰는 형태다.

본문은 한글, 전문 용어만 영문(`IPI`, `ReAct`, `ASR`). 논문 제목과 저자명은 원문 그대로.

## 4. 근거

**모든 수치는 PDF 원문과 대조한 뒤 적는다.** 초록의 요약값이 아니라 표의 값을 쓴다.

**초록과 표가 어긋나면 표를 따르고, 어긋난 사실을 감추지 않는다.**
SafeBranch 초록은 "과업 성공을 희생하지 않는다"고 했지만 표의 IS-Bench 과업 성공률은
0.656 에서 0.594 로 내려갔다. 그 숫자를 그대로 적었다.

**논문이 말하지 않은 것을 쓰지 않는다.** HiP-LR 의의에 "RECAP-THOR 도 함께 공개합니다"
라고 썼다가 원문에 공개 언급이 없어 걷어냈다.

**저자 표시(`*` 공동 1저자, `†` 교신저자)는 확인된 것만 넣는다.**
camera-ready 는 PDF 각주에 있고, 익명 심사본은 저자에게 물어야 한다.
홈페이지 preprint 페이지에는 이 표시가 없으니 거기서 가져오지 않는다.

**링크는 실재하는 것만.** 익명 심사본은 공개 주소가 없으므로 링크 줄 자체를 넣지 않는다.
camera-ready 는 OpenReview·GitHub 를 정보 박스에 버튼으로 넣는다.

## 5. 그림

- 원문 **Figure 1** 을 쓴다. 캡션 바로 위까지 크롭하고 원본과 대조해 잘림을 확인한다
- **webp, 폭 1200px, 편당 100KB 내외.** PNG 로 두면 5장에 2MB 가 넘는다
- 저장 위치는 `images/news/<학회><연도>/<slug>-fig1.webp`
- **PDF 자체는 저장소에 넣지 않는다**
- 민감한 내용(신체 이미지 등)이 든 그림은 **쓰기 전에 사용자에게 확인**한다

## 6. 배너 (여러 편 채택)

- 학회 공식 로고 + 행사지 사진을 합성한다. 로고는 **흰 배지 위**에 올려 대비를 확보한다
- 로고 원본이 작으면(예: 261×64) **배너 폭을 줄여** 로고를 원본 크기 가까이 둔다.
  억지로 키우면 뭉갠다
- 행사 정보(도시·기간)는 **검색으로 확인한 뒤** 넣는다. 홈페이지에 실리면 사실 주장이 된다
- 비율은 홈 카드와 같은 `1500/917`(≈1.64:1) 로 맞춘다

## 7. 목록·피드 연결

글 하나를 추가하면 **아래를 전부** 손봐야 한다. 하나라도 빠지면 글이 떠 있어도 못 찾는다.

| 대상 | 방법 |
| --- | --- |
| 기사 페이지 `news/<id>/index.html` | `news/build_article.py` |
| `news.json` (목록 데이터) | 직접 수정 |
| 목록 `news/index.html` | `build_news.py` |
| 홈 최신 소식 | `build_home_news.py` |
| RSS `news/index.xml`, `index.xml` | 직접 삽입 |
| `sitemap.xml` | 직접 삽입 |
| History 논문 제목 링크 (`index.html`) | 직접 수정 |
| Publication 카드 `[해설]` 링크 | 직접 수정 |

생성기 `build_news.py`, `build_home_news.py` 는 저장소 밖
`temp_works/2026-08-02-damilab-news-redesign/` 에 있고 `news.json` 도 거기 있다.

**같은 날짜에 여러 건이면 `news.json` 에 `ord` 를 준다.** 값이 클수록 앞에 온다.
허브 3, Main 2, Findings 1 로 썼다.

**여러 편이 한꺼번에 채택되면 논문별 글은 목록에서 감춘다.**
`news.json` 에 `hidden: true` 를 주면 News 탭 목록과 RSS 에서는 빠지고
`/news/<id>/` 주소는 그대로 열린다. 목록에는 허브 글 하나만 남기고,
논문별 글로는 허브·History·Publication 의 하이퍼링크로 들어가게 한다.
한 사건으로 카드가 여섯 장 깔리는 것을 막기 위해서다.
`sitemap.xml` 에는 남겨 둔다. 실재하는 페이지이므로 검색에는 잡혀야 한다.

**논문 그림 카드는 `fit: "contain"` 을 준다.** 카드 썸네일이 16:9 로 잘라내기 때문에
도식이 중간에서 끊긴다.

## 8. 검수

배포 전에 전부 통과해야 한다.

```bash
# 태그 균형
python3 -c "import re;raw=open('news/59/index.html',encoding='utf-8').read();
print([t for t in ['div','article','figure','ol','dl','a'] if len(re.findall(rf'<{t}[ >]',raw))!=raw.count(f'</{t}>')])"

# XML 문법
python3 -c "import xml.dom.minidom as M;[M.parse(f) for f in ['index.xml','news/index.xml','sitemap.xml']]"

# 삭제된 줄이 0인지 (바이트 편집 후)
git diff -U0 | grep -c '^-[^-]'
```

브라우저로는 **1280px 와 390px 양쪽**에서 확인한다.

- 가로 overflow 0, 콘솔 오류 0
- 그림이 실제로 로드됐는지 (`naturalWidth > 0`)
- **남색 배경 박스의 글자색.** CSS 특이도 때문에 흰 글씨가 먹히지 않아
  남색 위 검은 글씨가 된 적이 있다. `.na-body p.na-close` 처럼 특이도를 맞춰야 한다
- 스크린샷은 **페인트가 끝난 뒤** 찍는다. 바로 찍으면 이미지가 빈 칸으로 나온다

## 9. 자주 밟는 함정

| 함정 | 대응 |
| --- | --- |
| `git` 명령이 엉뚱한 저장소에서 실행됨 | 셸 작업 위치가 스크래치 폴더(`temp_works`)에 남는다. **git 명령마다 저장소 경로를 명시해 `cd`** 한다 |
| `sitemap.xml` 이 유효한 XML 이 아님 | `<?xml?>` 선언 앞에 빈 줄이 있으면 파서가 거부한다 |
| 생성기 앵커가 안 맞음 | 홈이 개편되면 `build_home_news.py` 의 `CLOSE` 앵커가 깨진다. 실패하면 실제 HTML 에서 앵커를 다시 찾는다 |
| 카드 이미지가 빈 칸 | lazy 로딩 + 페인트 지연. 검수 시 `loading='eager'` 로 바꾸고 스크롤한 뒤 확인 |
