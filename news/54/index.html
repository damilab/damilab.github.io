공격은 성공했는데 사용자는 모른다

Will the User Ever Know? Covert Indirect Prompt Injection Attacks on Tool-Using LLM Agents

TL;DR

공격 성공률(ASR)은 주입된 명령이 실행됐는지만 센다. 이 논문은 성공한 공격을 사용자가 최종 응답에서 알아채는 overt 와 알아채지 못하는 covert 로 나누고, 각각을 세는 OSR 과 CSR 을 제안한다. 성공한 실행 궤적을 뜯어보니 둘을 가르는 것은 주입된 행동 자체가 아니라 에이전트가 최종 응답 직전에 무엇을 했는가였다. 이 구조를 역이용한 공격 ICoA 는 AgentDojo 의 네 개 모델 전부에서 가장 높은 CSR 을 기록했다.

왜 이 문제인가

도구를 쓰는 LLM 에이전트는 송금, 메일 발송, 자격증명 변경처럼 현실에 영향을 주는 행동을 직접 수행한다. 공격자는 에이전트가 읽게 될 이메일, 검색 결과, 문서 같은 외부 콘텐츠에 명령을 심어 둘 수 있다. 에이전트는 그것을 tool observation 으로 읽고 그대로 따른다. 이것이 indirect prompt injection(IPI)이다.

이 분야의 표준 지표는 공격 성공률(ASR)이다. 주입된 tool call 이 실행되면 성공으로 센다. 그런데 ASR 은 주입된 작업이 실행됐는지만 볼 뿐, 그 성공이 사용자에게 보이는지는 보지 않는다. 사용자가 알아채지 못하면 이미 침해된 시스템을 계속 신뢰하게 되고, 탐지하거나 대응할 기회 자체가 없다. 같은 성공이 전혀 다른 결과를 낳는 것이다.

어떻게 풀었나

먼저 성공한 공격을 둘로 나눴다. 최종 응답에 아무 흔적을 남기지 않는 covert success 와, 응답만 보고도 사용자가 알아챌 수 있는 overt success 다. 이를 세는 지표가 CSR 과 OSR 이다. 판정은 GPT-4o 를 심판으로 두어 최종 응답이 주입된 행동을 드러내는지 보게 했고, Claude 4.5 Haiku 판정 및 사람이 라벨링한 궤적과 대조해 한 심판의 편향이 아님을 확인했다.

다음으로 왜 같은 공격이 두 결과로 갈리는지 확인했다. 차이를 만드는 것은 주입된 행동 자체가 아니었다. 최종 응답 직전에 에이전트가 무엇을 했는지가 갈랐다. 주입된 작업이 마지막으로 처리한 일이면 응답이 그것을 보고하고, 사용자의 원래 요청으로 돌아간 뒤 답하면 그 작업만 보고한다. 최종 응답이 가장 최근 행동을 요약하는 ReAct 형식에서 따라 나오는 구조적 결과다.

이 구조를 그대로 역이용한 것이 ICoA(Induced Covert Attack)다. 주입 페이로드를 두 지시문으로 감싼다. 앞쪽의 user framing 은 주입을 사용자의 후속 요청처럼 보이게 하고, 주입 직후의 RETURN anchor 는 주입을 먼저 처리한 다음 사용자의 원래 요청으로 돌아가라고 지시한다. 그 결과 주입은 궤적 중간에 놓이고 끝에는 사용자 작업이 온다.

결과

AgentDojo 벤치마크의 네 개 타깃 모델에서 평가했다.

  • 네 개 모델 전부에서 CSR 1위기존 최강 baseline 인 Impersonation message 대비 3.79 ~ 12.01%p 상승
  • LLaMA-3.3-70B 에서 최대 상승CSR 11.80% 에서 23.81% 로
  • 높은 ASR 이 은밀함을 뜻하지 않음같은 모델에서 ChatInject 는 ASR 32.14% 로 비슷하지만 CSR 은 2.63% 에 그침. ICoA 는 ASR 32.46% 로 같은 수준에서 CSR 23.81% 를 냄
  • RETURN anchor 단독으로도 효과기존 baseline 에 덧붙이기만 해도 CSR 이 최대 23.71%p 상승
  • 방어를 걸어도 우위 유지평가한 모든 detection 및 prompting 방어 아래에서 1위 유지

의의

주입된 작업을 실행하는 능력과 그것을 숨기는 능력은 별개다. ASR 하나로는 이 둘이 구분되지 않는다. 그리고 covert success 는 우연히 생기는 것이 아니라 설계로 유도할 수 있다. 사용자 관점의 지표가 IPI 평가에 따로 필요하다는 뜻이다.
